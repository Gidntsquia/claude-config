# Repo facts

- `~/.claude` files are symlinks into this clone, made by `./install.sh`. `./install.sh --check` prints a PASS or FAIL line per link.
- Evaluator tools: `local-tools/common/` links on every OS, `local-tools/wsl/` on WSL, `local-tools/macos/` on a Mac. `CLAUDE_CONFIG_INSTALL_OS=linux|wsl|mac|windows` overrides the OS for a test install in a scratch HOME.
- macOS tools: bash 3.2, `tmux`, `python3` and Firefox only; no AppleScript, no window bounds, no pane, split or tab. Openers only record an item; `win.sh show` opens it as a page in a separate Firefox (`-new-instance -profile <state>/ffprof/<id> -new-window <page>`), records its pid in `<state>/item/<id>.pid` and first kills the previous item's. A terminal item is a snapshot page built by `termpage.py` from `tmux capture-pane -e -p -S -`. No Firefox.app or a dead pid: `firefox failed:`, then `open` and `mode=browser`.
- A second Firefox started this way runs beside the user's own (seen with Firefox 161): the binary's pid stays the browser's pid, and SIGTERM closes it. A pid is killed only when its command line holds the item's profile path.
- Firefox writes `prefs.js` into a fresh profile about 0.5 s before its window is drawn; `win.sh` takes that file as "started" (else alive after 10 s).
- `phone-shot.sh` on macOS runs `local-tools/macos/phone-bidi.py`: headless Firefox over WebDriver BiDi, python3 stdlib, one `captureScreenshot` with a clip box per 390x844 screen. On WSL it is unchanged (Playwright Chromium). New Mac-only helpers go in `local-tools/macos/`, not `common/`, so the WSL install keeps its file names.
- Tests reach the Mac tools through `EVSHOW_FIREFOX_APP`, `EVSHOW_TMUX` and `EVSHOW_OPEN` (stand-ins), and the phone tool through `PHONE_FIREFOX_APP` and `PHONE_PORT_WAIT`. `./install.sh --check` reads `CLAUDE_CONFIG_FIREFOX_APP`.
- Tests: `test/run [quick|machine|docker|all]` is the one command (lint over the test files, then the `.bats` files in `test/<tier>/`, then pytest); last line `PASS <n> tests` or `FAIL <failed> of <n>`. New tests are `@test` cases copied from `test/quick/_template.bats`. Three old scripts are still run whole from `test/quick/legacy.bats` until split up: `test/evaluator-tools.sh` (`--live` on a Mac opens real Firefox windows), `test/install-scenarios.sh` (`SCN_ONLY=<case>`), `skills/run-agent/scripts/test.sh`. Test overrides are the `EVSHOW_*` variables read in `local-tools/macos/maclib.sh` and `local-tools/common/evshow.sh`.
- `wiki/` is its own git repo (the GitHub wiki). After changing a line of `agents/*.md` that the wiki quotes, run `helper-mcp/stamp-wiki` and `helper-mcp/check-wiki-quotes`, and commit inside `wiki/`.
- `settings.json` cannot be edited from a Claude session: the usage guard blocks writes to it. The user edits it.
- No file that installs into `~/.claude` names the author's own repos or projects; `test/owner-text.sh` checks it.
- A Mac set to always show scroll bars (a mouse, the CI runner) gives a long page 375 css px; `phone-bidi.py` sets `ui.useOverlayScrollbars` and hides the root scroll bar so pictures stay 780 px wide. `PHONE_OVERLAY_SCROLLBARS=0` reproduces the case.
- bats: `test/run` uses `test/vendor/bats-core/bin/bats` when that submodule exists, else a `bats` on PATH (`brew install bats-core`). The assertion libraries (bats-support, bats-assert, bats-file) load from `test/vendor/`; while absent, `test/helpers/assert-fallback.bash` supplies the same names. Homebrew refuses the `bats-core/bats-core` tap as untrusted, so the libraries cannot come from brew.
- An old script run under bats must write to a file, not a pipe, with fd 3 closed (`run_legacy` in `test/helpers/legacy.bash`): `skills/run-agent/scripts/test.sh` leaves `sleep 600` processes behind, and a pipe they hold keeps bats waiting 10 minutes.
