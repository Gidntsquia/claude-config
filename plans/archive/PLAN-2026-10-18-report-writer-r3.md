## Requirements
1. (user) Decision chart is measured bars again: one bar per candidate, value printed at the bar end, one thin spread line per bar, nothing else (no run dots, no shaded band, no bracket, no second panel). The change-vs-baseline panel and its check.py `decision_chart` rule are removed.
2. (user) The writer chooses each bar chart's axis start itself: report.json `chart.axis_min` (number or 0) plus `chart.axis_reason` (one line). The prompt states the judgment in general terms: start above zero when the bars would otherwise look the same length and the decision rides on their difference; keep zero when sizes relative to zero matter (shares, stacked time). No threshold hard-coded in render.py.
3. (user) When `axis_min` > 0, render.py prints the axis as "<min> – <max> <unit> (axis does not start at 0)" and draws a break mark at the left of every bar. check.py `axis_note` fails a chart with axis_min > 0 that lacks the label or the break mark, and fails any chart with no `axis_reason` when axis_min > 0.
4. (user) One agent run: run.sh `build` calls the writer once with no mode word; the agent writes `report.json` and `numbers.json`; render.py then writes `out/desktop/report.html` and `out/phone/cards/*.png` from that same report.json. `run.sh desktop|phone` keep working as "build if missing, then render + check that mode". The writer prompt no longer takes phone/desktop; the mode is render.py's argument.
5. (user) Data-wins rule in report-writer.md: when a candidate is measured in more than one file, the decision table uses the source with the most runs per arm; the other source is listed under Also measured with its n. check.py `most_runs` fails a decision-table row whose n is smaller than the largest n for that candidate in the fixture (fixture/TRAPS.md names the expected n per candidate). check.py `modes_match` fails if the desktop and phone decision tables differ in any cell.
6. (user) `agents/report-checker.md`: frontmatter `model: opus`, `effort: high`, tools Read/Glob/Grep/Bash/Write. Input: data dir, question, the report dir (report.json, numbers.json, rendered HTML). It (a) reads only the data dir and question first and writes `checker/cold.md`: its own verdict, next action and deciding figure with source; (b) then reads the report and lists every claim or figure that looks off (verdict differs from its cold one, direction word without spread, n that looks too small for what the fixture holds, a trap-like quantity shown as a plain figure, a figure whose magnitude does not fit its source); (c) recomputes only those from the source files, never the whole numbers.json; (d) writes `checker/findings.json`: list of {key or claim, what the checker found, source, severity}. Empty list = clean. The writer invokes it via the Agent tool (tools list gains `Agent`); if this install refuses nested subagents, run.sh chains writer → checker → writer and the plan's Facts line is corrected by the worker in WORKER_NOTES.
7. (user) Writer loop: after the first full report.json the writer runs the checker, re-derives only the flagged figures, changes the report where the checker was right, and re-runs the checker; at most 2 loops. Findings still open after the second loop go into the Wrong-or-missing box as "checker: <finding>" (default). No question to the user.
8. (user) The "How this was checked" line gains: checker loops run, findings raised, findings fixed, findings still open. check.py `checker_line` fails if the line or `checker/findings.json` is missing.
9. (user) `run.sh planted` copies the built output and runs the checker alone three times, each on one corruption: (a) one deciding numbers.json value shifted by 10%; (b) one decision-table verdict flipped drop↔keep with numbers unchanged; (c) one TRAPS.md item removed from Wrong-or-missing. Pass = each run's findings.json names that key, row or trap. Exit 1 naming the case that was missed.
10. (user) `agents/report-writer.md` frontmatter becomes `model: fable`; README agent list and CHANGELOG Unreleased mention the checker and the model change; RUBRIC.md gains rows for R1–R3 (few marks, honest axis), R5 (modes match) and R6–R8 (checker); REVIEW.md records round 3 from the user's reading.
11. (default) Everything else in plans/archive/PLAN-2026-10-17-report-writer-r2.md (R1–R13 and both amendments as far as not replaced above) still holds; the round-2 amendment's "change panel" text is superseded by R1–R3 here.
