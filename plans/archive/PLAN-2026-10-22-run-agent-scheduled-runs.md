# Spec: /run-agent scheduled runs (at a time / after the 5h window) and forgiving argument parsing

## Ask
"I want to add to 'run at a time' or 'run after the current 5hr window ends' functionality to /run-agent. Further, check the logs of the recent runs of /run-agent -- I've been running it on Haiku since its cheapest that way, and Haiku has struggled to read what model and effort I want" (2026-10-22).
Answers, verbatim:
- Waiting: "Option 3; the session should not need to be alive, though. It should simply make a detached runner that will run the run agent script at the specified time. The idea is that it will guard against hitting the usage cap— especially when I run overnight"
- Time words: clock time (`at 9pm`, `at 21:40`), delay (`in 2h`, `in 90m`, `in 1h30`), window (`after window`, `next window`, `when the window resets`), `--at <time>` flag form; "Have it be flexible; I usually write the commands from my phone, which means I want it allow me to be a bit lazy at times with formatting"
- Parsing fix: "Option 3 [script parses, SKILL.md keeps a short table]; the model should always double check anything the script flags (i.e if i make a small typo)"
- Right result: replay the logged phrases; dry-run shows the command and time; live check once in Haiku.
- Fire target: "Original pane, else a new tmux window".
- Cap guard: "Time only, no usage check" and "Add `until <time>` to hand-pick the window".
- Typo check: "Auto-correct near matches, ask only when unsure".
- Pending runs: "The model should be able to check if I ask it and cancel if need be".

## What to build
Two changes to `skills/run-agent/` (SKILL.md, scripts/run-agent.sh, scripts/test.sh). First, the script takes over parsing: `S --parse` turns the raw `$ARGUMENTS` string, however loosely typed from a phone, into agent, prompt, directory, claude flags (model and effort included), force, and an optional run time, auto-correcting near-miss words and flagging only what it cannot place; SKILL.md shrinks to "parse, resolve flags, confirm, run" plus a short table so the model can explain what it understood. Second, a run time (`at 9pm`, `in 2h`, `after window`, `--at ...`, with an optional `until <time>`) makes the script write a detached runner instead of swapping the pane now; at the time it respawns the original pane (or a new tmux window) into the same `claude --agent ...` command, so overnight runs start when the 5-hour usage window has reset. Pending runs can be listed and cancelled through the script, and the model does that when asked.

## Facts
- Log review (`~/.claude/projects/*/*.jsonl`, 2026-10-14 to 10-22, 90 `/run-agent` calls): on Haiku the script's usage line or a dropped flag came back for `worker model=fable effort =medium` (10-18), `worker -model fable -effort low` (10-22 15:59), `worker —model fable —effort low` (10-22 07:05, em dashes), `worker fable low effort` (10-22 17:49: "low effort" dropped, then re-added after a `claude --help` lookup). Each cost one or two extra turns ("You know what I meant"). Forms that worked: `worker, model=fable, effort=medium, force`, `worker force —model fable —effort medium`, `worker, opus+medium effort`. Phone typing also produces curly quotes (`“I’m on my phone”`) and a newline inside the prompt; those were read correctly.
- Cause: SKILL.md maps `using|with|on <model>` only; no effort mapping; only `--` flags; "any other unquoted word -> usage".
- `claude --help` (2026-10-22): `--effort <level>` takes `low, medium, high, xhigh, max`; `--model <model>` takes `fable`, `opus`, `sonnet`, `haiku` or a full name; `-n, --name`.
- 5-hour window reset: `GET https://api.anthropic.com/api/oauth/usage` with `Authorization: Bearer <~/.claude/.credentials.json .claudeAiOauth.accessToken>` and `anthropic-beta: oauth-2025-04-20` returns `five_hour.{utilization,resets_at}` (ISO 8601 with offset) and `seven_day`. Used by `~/files/agent-eval-experiment/planner/run_windows.sh` and `report-writer/fixtures/token/data/usage-snap.sh` (worked 2026-10-03). A stale token returns no `five_hour`; opening any claude session refreshes it.
- The statusline JSON carries `rate_limits.five_hour.used_percentage` but no reset time.
- `atd` is inactive on this box; tmux 3.x is present. The runner must not depend on `at` or cron.
- test.sh today runs the script outside tmux and inside a private tmux server (`tmux -L run-agent-test-$$`) with a fake `claude` on PATH.

## Requirements
1. (user) `S --parse '<raw $ARGUMENTS>'` prints one block (`key<TAB>value` lines, or JSON) with: agent, prompt, dir, flags (claude flags in `--long` form), force (0/1), at (epoch seconds or empty), at_text (what was read), until (epoch or empty), corrections (list of `<typed> -> <read>`), unsure (list of tokens it could not place), and dry (0/1). The model treats this output as the parse; it never re-parses the string itself.
2. (user) Accepted forms, anywhere outside the quoted prompt, case-insensitive: flags with `--`, `-`, `—` (em dash) or `–` (en dash); `key=value`, `key = value`, `key value`, `key: value` for `model` and `effort`; a bare model word (`fable`, `opus`, `sonnet`, `haiku`) means `--model`; a bare effort word (`low`, `medium`, `high`, `xhigh`, `max`) or `<effort> effort` / `effort <effort>` means `--effort`; `<model>+<effort>` (`opus+medium`); commas between tokens are separators; curly quotes `“ ” ‘ ’` open/close a prompt like straight ones, a newline inside the prompt is kept. Existing mappings (`using|with|on <model>`, `yolo`, `resume|continue`, force words, `in <dir>`, `--cwd`, `-C`, path tokens) stay as in SKILL.md today.
3. (user) Near-miss words: a token within edit distance 2 of a known word (agents from `--list`, model and effort words, force words, `window`, `at`, `in`, `after`, `until`, `effort`, `model`, `dry`) is taken as that word and listed under corrections; shown in the confirmation as `(fabel -> fable)`. Anything else goes under unsure. One unsure token -> the model asks one AskUserQuestion with its best reading as the first option ("I read `efort lo` as `--effort low`. Right?"), options Yes / It is part of the prompt / Drop it; then the normal flow. With force and an unsure token, the question is still asked (force skips only Run?).
4. (user) Time forms: `at 9pm`, `at 9:30pm`, `at 21:40`, `at 2140`, `at 9` (today if still ahead, else tomorrow; a bare hour 1-12 with no am/pm picks the next occurrence); `in 2h`, `in 90m`, `in 1h30`, `in 2 hours`, `in 45 min`; `after window`, `after the window`, `next window`, `when the window resets`, `after reset`, `window`; flag forms `--at <same words>`, `--in <delay>`, `--after window`. Times are local (America/New_York, the machine's TZ); the confirmation prints `at 9:40 PM ET (in 3h 12m)`. (default) An unparseable time after `at`/`in` goes under unsure.
5. (user) `until <time>` (same clock forms) after a window phrase: if the reset instant is later than that time, the run is not scheduled; `--parse` prints `until` and the runner logs `skipped: reset 7:40 AM ET is after until 7:00 AM ET` and does nothing. (default) `until` without a window phrase is unsure.
6. (user) Window time is fetched at scheduling time from the usage API (Facts). No `five_hour.resets_at` (stale token, no network) -> `--parse` prints `at_error: usage API: <reason>; open any claude session to refresh the token` and the model relays it and stops; nothing is scheduled. (default) At fire time the runner re-fetches once; if the new reset is later than the scheduled one, it waits for it (max one further hour), otherwise it runs at the scheduled time. No usage-percentage check (user).
7. (user) Scheduling: with `at` set, `S <agent> ... --at <epoch> [--until <epoch>]` writes `~/.claude/run-agent/jobs/<id>.json` (id, created, run_at, until, at_text, cwd, pane id, tmux session, full claude argv, shown command) and starts a detached runner (`setsid nohup`, survives this claude session and pane ending, not a reboot) that sleeps to run_at, then fires. It prints `scheduled #<id>: <shown command> at 2:40 AM ET (after window, in 3h 12m)` and exits 0; the current session is not replaced.
8. (user) Fire: the runner respawns the recorded pane (`tmux respawn-pane -k -t <pane> -c <cwd>`) into the recorded command, exactly as a non-scheduled run would, with the first pane line `scheduled run #<id> fired at 2:40 AM ET: <shown command>`. Pane gone -> `tmux new-window -t <session> -n "<agent>: <folder>"` in the recorded session; tmux server gone -> `tmux new-session -d -s "<agent>: <folder>"` running the command. Outcome appended to `~/.claude/run-agent/jobs.log` (`fired`/`fired in new window`/`fired in new session`/`skipped`/`cancelled`), job file moved to `done/`.
9. (user) `S --jobs` lists pending runs: `#<id>  <shown command>  at <ET time> (<at_text>, in <h>h <m>m)  [until <ET time>]`, or `no scheduled runs`. `S --cancel <id>` kills the runner and logs `cancelled`; `S --cancel` with exactly one pending job cancels it. SKILL.md: when the user asks what is scheduled or to cancel, the model runs these and relays the output; with several pending and no id, AskUserQuestion which.
10. (user) Dry run: `dry`, `dry run`, `--dry-run` anywhere -> the model prints the full command, the directory, the ET run time and the usage reset time it fetched, and stops without scheduling or respawning. Also `S --dry-run <...>` for the script alone.
11. (default) Confirmation (step 5 of SKILL.md) with a time: `Schedule: claude --agent worker "." --model fable --effort low --name "worker: claude-config (fable)" at 2:40 AM ET (after window, in 3h 12m) (in /home/jaxon/files/claude-config)?`, with corrections appended as `(read: fabel -> fable)`. Options "Yes, schedule it" / "No". Force skips it as today.
12. (default) `--name` adds ` (<model>)` as today; effort is not in the name.
13. (user) SKILL.md: steps become parse (`S --parse`), resolve unsure/corrections (R3), directory (`S --resolve`, unchanged), validate agent, confirm, run or schedule; a short table (under 15 lines) of the accepted word forms so the model can explain what it read; nothing in it asks the model to parse flags itself. Keep the usage reply for truly unparseable input (two directories, no agent after a question).
14. (user) test.sh gains a parse suite: every distinct argument string from the log review (Facts, including the curly-quote and multi-line prompts, `worker, model=fable effort = medium, force`, `worker fable low effort`, `worker —model fable —effort low`, `worker -model fable -effort low`, `worker, opus+medium effort`, `evaluator “I’m on my phone” force`, `claude --agent evaluator "."`) plus at least 12 time strings and 4 typo strings, each asserting the exact `--parse` output; and a scheduling suite in the private tmux server with a fake usage API (env var pointing at a local JSON file) and a run time 3 s ahead, asserting the pane respawned, the log line, `--jobs` before/after, `--cancel`, `until` skipping, and the pane-gone and server-gone branches. Prints `N passed, M failed`.
15. (user) Live check: run `/run-agent worker fable low effort at 9pm dry` once in Haiku; the confirmation must show `--model fable --effort low` and `9:00 PM ET`; the transcript is cited in WORKER_NOTES.md.
16. (default) README.md and the skill's `description`/`argument-hint` mention the time forms and `jobs`/`cancel`; CHANGELOG.md gets an entry.

## Constraints
- Bash 5 + tmux + python3 (stdlib only, for the usage API and time parsing if easier than bash) as the repo already uses; `jq` is on the box. No `at`, cron, systemd, or new dependencies.
- `~/.claude/run-agent/` is the only new state directory; nothing written inside the repo at run time.
- The script never creates directories except `~/.claude/run-agent/`; `mkdir -p` of a missing `in <dir>` stays the model's step after Yes.
- Existing test.sh cases keep passing; existing behaviors (force, dir, resume, name) unchanged.
