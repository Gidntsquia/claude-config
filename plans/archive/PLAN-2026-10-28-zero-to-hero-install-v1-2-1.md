# Spec: Zero-to-hero install of claude-config by telling Claude the repo link, tested on fresh Linux/WSL, Mac and Windows, released as v1.2.1

## Ask
"This project is meant to store my claude setup such that a user on a fresh device can download it and immediately get access to all the features I used on a daily basis. However, the fresh setup doesn't work very well at current time. My brother tried to install the mac version of the config into his setup, and it totally failed-- the profile is hard-coded to go to the "september-trip" folder, which wasn't on his computer and thus crashed his iterm whenever he opened it. I want to fix that issue and any other issues we can find that prevent a new user on a fresh device from going from zero to hero instantly with this repo." Wants: install instructions so Claude can be given the repo link and told "install"; test in a VM/Docker for PC, Mac, and PC-with-WSL; the installing Claude asks about defaults and decisions (where to store projects, make the default profile mine, etc.); when local preferences exist the default is to leave them and purely augment (some users only want the agents); a new 1.2.1 release; the one-sentence install advertised very clearly at the top of the README; everything works out of the box with no further steps; the installing Claude then gives a quick tour (status line, 4 split-screen tmux panes, planner/worker/evaluator workflow).
Answers, verbatim:
- Install path: "INSTALL.md + install.sh flags"
- Existing files: "Option 1 [Keep theirs, add only what's missing], except for key things like if the user has a planner/worker/evaluator agent already-- in that case, we should bring up the clash and ask the user what they want to do."
- Testing: "Docker Ubuntu for the WSL/Linux path", "GitHub Actions matrix: ubuntu + macos + windows runners", "Windows Sandbox / Hyper-V VM for the WSL-from-zero path", "I'll try on my Mac once we get to a good point. We'll need to do a handoff since I'm currently working on this on my PC"
- Proof: "install.sh --check prints a pass/fail list", "Opening the terminal shows 4 tmux panes + statusline", "The three agents run end to end on a toy project", "No file in the repo names jaxon or /Users/… after install", "We should have things be generalized if we can and avoid hardcoding paths or other things"
- Mac terminal: "Generic 'Claude tmux' profile, opt-in"
- Tour: "Live demo in the chat", "Open the wiki Getting Started page in the browser", "Open a new terminal tab to show the 4 panes", "Tour text lives in INSTALL.md"
- Install questions: "Projects folder", "Terminal setup: tmux 4 panes + prompt + default profile", "Status line: Jaxon's / keep mine / plane theme", "settings.json: merge Jaxon's keys / keep mine / replace"
- Release: "Tag + GitHub release + CHANGELOG/RELEASE_NOTES, same shape as v1.2.0", "Wiki pages updated too", "Release only after the Mac handoff test passes", "UPDATING.md covers 1.2.0 → 1.2.1"

## What to build
A new `INSTALL.md` that a Claude session follows when a user pastes the repo link and says "install": it clones, asks four menu questions, runs `install.sh` with flags that install only what was chosen, runs `install.sh --check`, and gives a fixed tour. `install.sh` grows component flags, a `--projects` folder, a merge mode for `settings.json`, a clash check for same-named agents, `--check`, and a saved-choices file so updates re-apply the same choices. Every personal path (`september-trip`, `/Users/jaxon`, `~/files`, `/mnt/c/Users/Jaxon`, `/home/jaxon`) leaves the installed files or is derived at install time. iTerm2 gets a generic opt-in "Claude tmux" profile and the personal plist leaves the repo. A Docker script and a GitHub Actions matrix test the install on clean ubuntu, macos and windows; a Windows Sandbox script covers WSL-from-zero. README opens with the one-sentence install. Everything but the tag is finished and a `plans/HANDOFF.md` tells the user how to test on his Mac; the tag and GitHub release v1.2.1 follow once he says it passed.

## Requirements
Install entry point
1. (user) README's first section after the title is "Install in one sentence": tell Claude Code `Install https://github.com/Gidntsquia/claude-config following its INSTALL.md`, in a copyable code block, with one line saying Claude asks four questions and leaves existing settings alone. The old Quickstart stays below it as "Manual install".
2. (user) `INSTALL.md` is written for a Claude session (same voice and STOP convention as `UPDATING.md`): check `claude`, `git`, `bash` (`tmux` only if terminal setup is chosen; install via brew/apt with the user's yes); clone to `~/.claude-config` unless the user names a folder; detect OS (Darwin / WSL via `/proc/version` / other Linux / native Windows = Git Bash); read `~/.claude` for existing files; ask the four questions in R3 with AskUserQuestion; run `./install.sh` with the matching flags; run `./install.sh --check`; give the tour in R12. It never edits a user file by hand; `install.sh` does every change.
3. (user) The four questions, each with the default first: (a) projects folder: `~/files` (default), `~/code`, `~/Projects`, other; (b) terminal setup yes/no (tmux 4 panes, tmux.conf, starship prompt, Nerd Font check, Windows Terminal or iTerm2 "Claude tmux" profile, and make it the default profile); default yes when no `~/.tmux.conf`/no custom profile exists, else no; (c) status line: Jaxon's squid (default when none set), plane theme, keep mine; (d) `settings.json`: merge (default), keep mine, replace. Agents and skills are not asked about: always installed, except R5.
4. (default) Native Windows without WSL: INSTALL.md installs agents, skills, settings merge and CLAUDE.md through Git Bash and says the status line, tmux and terminal setup need WSL, linking the wiki page Setting-Up-WSL. It never fails; it says what it skipped.
Existing files and clashes
5. (user) Before linking `agents/`, `install.sh` lists any file in `~/.claude/agents/` whose name matches one of the repo's agents and is not already a link into this clone. If any, it stops with exit code 3 and prints them; INSTALL.md then asks per agent: keep mine (repo agent linked as `<name>-claude-config.md` and the tour says so), use Jaxon's (theirs moved to `<name>.pre-link.md`), or skip. Flags `--agent-clash keep|replace|skip` apply the answer. Skills with the same name are handled the same way.
6. (user) `settings.json` merge: a JSON deep merge where the user's existing value wins for every key that exists in their file (including inside `permissions.allow/deny` lists, which are unioned), and the repo's value fills only missing keys; result written to `~/.claude/settings.json` as a real file (not a symlink), their original kept as `settings.json.pre-link`; `--settings replace` links the repo file as today; `--settings keep` touches nothing. The merge is done by a Python script in the repo (`python3` only, no third-party packages) and the repo copy of `settings.json` loses the `/home/jaxon/ai-test` trusted-repo note.
7. (user) `CLAUDE.md`: linked when the user has none; otherwise left alone and `install.sh` prints the one `@` import line they can add. `CLAUDE.md` line 8 says the config lives in the clone path recorded at install, not `~/files/claude-config`. `statusline.sh` is linked only when `--statusline squid|plane` is given; `keep` leaves `statusLine` in settings as the user had it and the merge does not add it.
8. (default) Choices are saved in `~/.claude/claude-config.json` (`projects`, `terminal`, `statusline`, `settings`, `agentClash`, `repo`, `version`). Rerunning `install.sh` with no flags reuses them; `UPDATING.md` gains the 1.2.0 → 1.2.1 step "run `./install.sh` and it reapplies your saved choices; if the file is missing, follow INSTALL.md's questions once".
Generalizing paths
9. (user) After install, `grep -rIl -e jaxon -e '/Users/' -e '/home/' -e september-trip` over every installed file (the clone minus `.git`, `wiki/`, `archive/`, `plans/`, `examples/`, `agents/evals/`) prints nothing. Paths come from `$HOME`, the chosen projects folder (written to `~/.claude/claude-config.json` and read by `tmux-quad`, helper.md and the Mac profile at run time), `$WSL_DISTRO_NAME`, `cmd.exe /C echo %USERPROFILE%` for the Windows user, and `$(dirname "$(readlink -f ~/.claude/agents)")` for the clone. VS Code and Firefox paths in `wsl/CLAUDE.local.md` and `agents/evaluator.md` are resolved from `%LOCALAPPDATA%`/`%ProgramFiles%` or `command -v`; the fixed report-writer Playwright path becomes an env lookup with a fallback that says what to install.
10. (user) iTerm2: `iterm2/com.googlecode.iterm2.plist` and `september-trip.json` are deleted. `iterm2/DynamicProfiles/claude-tmux.json` defines one profile "Claude tmux" whose command runs `$HOME/.local/bin/tmux-quad` (same script as WSL, moved to a shared `bin/`, reads the projects folder from `~/.claude/claude-config.json`, falls back to `$HOME`), working directory `$HOME`, plus an `iterm2/claude-colors.itermcolors` export of the current gruvbox colors and font name. Installed only with `--terminal`, only when `/Applications/iTerm.app` exists; `--terminal` also sets it as the default profile (`Default Bookmark Guid`) when the user chose that, and prints how to undo it. Opening iTerm2 on a machine with no such folder never fails: the script `cd`s to `$HOME` when the folder is missing.
11. (user) WSL terminal setup keeps today's behavior but the Windows Terminal profile is made default only when the user said yes in R3(b); the volume task is installed only with `--terminal` and is listed as a separate line in `--check` output.
Tour
12. (user) INSTALL.md's "Tour" section is fixed text Claude reads out after `--check` passes, filling in only what was installed: (1) runs `bash ~/.claude/statusline.sh --preview` (squid or plane) and says what each segment means; (2) if terminal setup was installed, opens one new terminal window/tab with the 4-pane layout (`wt.exe` on WSL, `open -a iTerm` with the profile on Mac) and says each pane is for one agent; (3) names the three commands `claude --agent planner`, `worker "."`, `evaluator "."` with one line each and `claude --agent helper` as the guided path; (4) opens https://github.com/Gidntsquia/claude-config/wiki/Getting-Started in the default browser; (5) ends with one "try this now": `mkdir <projects>/my-first-app && cd $_ && claude --agent planner`. Fits on one screen (≤ 25 lines of chat).

## Constraints
- Bash for `install.sh`, `tmux-quad`, `--check`, Docker script (bash ≥ 3.2 for macOS stock bash: no associative arrays); Python 3 standard library only for the settings merge and `wt-profile.py`; PowerShell for the Sandbox script; GitHub Actions YAML. No new runtime dependencies for users beyond git, bash, python3, curl, optional tmux/starship.
- Keep every existing feature working for the user's own PC (WSL, `~/files`, plane/squid, volume task) when run with saved choices.
- Agent files keep the rules in `docs/agent-style.md`; prose in README/notes/wiki follows `skills/write-readme` and `docs/ai-tells.md`.
