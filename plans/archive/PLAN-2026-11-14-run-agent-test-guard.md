## Requirements
Part 1: the fix (only files under `skills/run-agent/`)
1. (user) test.sh exports `RUN_AGENT_TEST=1` before its first call of `$S`. With that variable set to `1`, `claude_environ()` returns `{}` whatever the parent processes are.
2. (default) With `RUN_AGENT_TEST=1`, `claude_argv()` also returns its "no claude parent" value, so no case's result depends on which session ran test.sh. A case that needs an agent parent (line 705) sets it explicitly through `RUN_AGENT_FROM` or its own `exec -a claude` wrapper, and the flag does not hide a wrapper the test itself made; if both cannot hold, `RUN_AGENT_FROM` is the way.
3. (user) Tmux refusal: with `RUN_AGENT_TEST=1`, every code path in `run-agent.sh`, `launch.py`, `runner.sh` and `jobs.py` that would run `tmux respawn-pane`, `kill-pane`, `kill-window`, `kill-session`, `new-window`, `new-session`, `split-window` or `send-keys` first checks the socket it is about to use. Allowed: a socket whose basename starts with `run-agent-test-`, or a socket path under the directory named by `RUN_AGENT_TEST_DIR` (test.sh exports it as `$T`). Anything else, including an empty or default socket: the tmux command is not run, stderr gets the one line `test mode: refusing tmux <subcommand> on <socket or "default server">`, exit 2. Without the flag, behavior is byte-for-byte what it is today.
4. (default) Job-store refusal: with `RUN_AGENT_TEST=1`, any write to the job store (schedule, cancel, revive, log) exits 2 with `test mode: refusing the real job store` unless `RUN_AGENT_HOME` is set and resolves outside `~/.claude`. Reads (`--jobs`, `--health`) are refused the same way.
5. (default; widens the user's "every hook case") test.sh unsets `TMUX` and `TMUX_PANE` once, right after the trap line, for the whole script. A case that needs tmux sets both itself to a pane on the private `-L "$SOCK"` server or on `$T/split.sock` / `$T/group.sock`. The four `--hook` cases (lines 700-705) run either with no tmux (expecting `not inside tmux` / dry output) or with TMUX pointing at a throwaway pane on `-L "$SOCK"`; none can see the caller's pane. The per-line `env -u TMUX -u TMUX_PANE` may stay.
6. (user) Canary case in test.sh, named `canary: test run inside a claude tmux pane leaves it alone`: on the private `-L "$SOCK"` server it opens a pane whose foreground process is a wrapper with argv[0] `claude` (so `/proc` shows a claude parent with that pane's real `TMUX`/`TMUX_PANE`), and from inside it, as children of that wrapper, runs the hook inputs of lines 700-705 with `env -u TMUX -u TMUX_PANE` exactly as line 704 does today. PASS only if the pane's `#{pane_pid}` is the same before and after, `#{pane_dead}` is 0, and the line-704 input answers `not inside tmux`.
